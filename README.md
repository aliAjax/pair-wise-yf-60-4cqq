# 无障碍人工审计协作工作台

源提示词摘要：审计员现场断网时先保存问题包，回办公室后合并进同一工作台；按问题指纹认出同一处缺陷，保留两边新增的复现步骤、影响人群和证据；同一问题的状态冲突按操作时间线仲裁；已关闭问题重新打开后旧复测结论失效；合并失败重试只补缺口，重复导入同一包不产生重复记录。

## 技术栈

SolidStart、TypeScript、Park UI、Solid Router、TanStack Query、Solid Store、Modular Forms、Zod、Solid i18n primitives。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62025`

## 离线合并流程

1. **导出问题包**：现场断网前点击「导出问题包」，下载 `audit-pack-*.json`（格式 `a11y-audit-pack/v1`）。
2. **现场记录**：在另一台机器/同一工作台继续录入（演示中由「生成『断网返回』演示包并合并」一键构造：现场补充了步骤、影响人群、证据，新建了一个问题，且与办公室对同一问题写入了不同状态）。
3. **导入合并**：回办公室后「导入问题包并合并」：
   - **问题指纹**（`src/lib/audit/fingerprint.ts`）：对标题+业务流程+复现步骤做规范化哈希，空白/标点差异不影响识别；同指纹即同一处缺陷。
   - **字段级合并**：两边新增的复现步骤、影响人群、证据按贡献条 ID 全量保留，后导入的不会整条覆盖原记录；新问题才新增。
   - **状态时间线仲裁**：重放双方流转（共享历史之后按操作时间排序），较新的**有效流转**决定当前状态；较早的不同流转、以及基于已分叉旧状态的无效写入，都作为**冲突记录**在冲突面板可见。
   - **复测失效**：问题重新打开后，该时间点之前的旧复测结论立即标记为失效（UI 划线显示）。
   - **失败重试 / 幂等**：每个包记录 `appliedIssueIds` 检查点，合并中断后重试只补未合入的问题；完整导入过的包再次导入直接跳过，问题、冲突、字段都不会重复。
4. **持久化**：合并结果、冲突记录、导入检查点全部存入 localStorage（`a11y-audit-v2`，自动从 v1 迁移），重开浏览器仍可见。

页面还提供「模拟合并失败后重试」按钮，直接演示检查点补缺口；顶部冲突面板展示仲裁双方、时间、来源与裁决说明。

## 合并引擎测试

纯函数引擎位于 `src/lib/audit/`，不依赖 DOM：

```bash
npm test      # tsx scripts/merge.test.ts，10 个用例
npm run check # tsc 类型检查
npm run build # SolidStart 构建
```

覆盖：指纹规范化识别、字段级合并不覆盖、新问题新增、两种方向的状态仲裁、无效分叉流转可见、重开后旧复测失效、相同状态不冲突、整包重复导入跳过、失败重试只补缺口、无共同历史仅指纹相同的合并。

## 可用流程

- 创建审计问题，保存复现步骤、影响人群、证据和严重程度。
- 问题按待分诊、修复中、待复测、已关闭和重新打开流转。
- 将重复问题合并到主问题，保留来源关系和操作审计。
- 开发修复与复测结果分开记录，复测失败自动重新打开并使旧复测结论失效。
- 离线问题包导出/导入、指纹字段级合并、状态冲突仲裁与检查点重试。
- 支持跳过导航、可见焦点、读屏提示、`N` 快捷键聚焦新建问题、`Ctrl+Enter` 提交。
